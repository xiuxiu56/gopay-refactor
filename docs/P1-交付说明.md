# P1 交付说明：持久化任务引擎与实时数据接口

## 阶段结论

P1 已完成。重构项目现在可以通过根目录 `main.py` 独立启动，并拥有以 SQLite 为唯一状态源的任务执行后端。应用启动时会升级数据库、加载加密密钥、恢复过期任务并启动固定 Worker 池；关闭时会先优雅停止 Worker，再释放数据库引擎。

本阶段没有修改旧项目文件，也没有让新 Worker 调用旧版 JSON 队列或账号保存函数。

## 启动入口

```bash
cd gopay-refactor
.venv/bin/python main.py
```

入口默认等价于 `gopay-v2 serve`，支持 `--host`、`--port` 和 `--database`。即使项目尚未执行 editable install，入口也会先加入本地 `src` 路径。

## 任务状态机

任务状态集合如下：

```text
queued ──领取──> running ──成功──> succeeded
  ▲                  │
  │                  ├─临时错误──> retry_wait ──到期──> queued
  │                  ├─等待输入──> waiting_input ──提交──> queued
  │                  ├─永久错误──> failed
  │                  └─副作用中断──> needs_review
  └──────────── 人工重试 ─────────── failed/cancelled/needs_review
```

核心保证：

- 领取使用单条 SQLite `UPDATE ... RETURNING`，状态判断与锁定在同一事务内完成。
- 每次领取生成唯一 `task_attempts` 记录，并写入 `task_events` 和 `change_log`。
- `locked_by` 与 `locked_until` 形成 Worker 租约，Supervisor 按固定周期续租。
- 临时错误按 `base × 2^(attempt-1)` 退避；达到 `max_attempts` 后进入 `failed`。
- 只读或幂等 Handler 的过期租约可自动恢复；支付扣款等副作用 Handler 进入 `needs_review`。
- 取消会使运行中的 Worker 失去状态所有权，并清除任务资源租约和未消费输入密文。

## 固定 Worker 池

- Worker 数量由 `GOPAY_WORKER_COUNT` 固定配置，范围为 1–64。
- Worker 线程均为非 daemon，应用退出会等待优雅停止。
- 一个 Supervisor 维护所有活跃任务的心跳，并清理超时的一次性输入。
- 业务 Handler 通过 `TaskContext` 更新进度、保存检查点、检查取消、消费输入和申请资源租约。
- 自动化测试验证 100 个任务在 12 个并发领取者下没有重复领取，实际业务并发不会超过配置的 Worker 数量。

## OTP 与一次性输入

- 任务通过 `waiting_input` 状态释放 Worker，而不是阻塞线程等待。
- 输入值使用 AES-GCM 加密，查重使用带命名空间的 HMAC-SHA256。
- 输入类型会与加密检查点中的预期类型核对。
- 提交后任务重新进入 `queued`；消费事务会立即清空 `value_ciphertext` 并记录 `consumed_at`。
- 等待超时或取消任务时，残留的未消费密文也会被清除。

## 资源租约

`resource_leases` 通过 `(resource_type, resource_key)` 唯一约束保证排他占用。获取动作使用 SQLite UPSERT；只有租约已经过期或租约属于当前任务时才允许更新。

当前约定的资源类型包括：

- `account`：账号 ID。
- `phone`：手机号记录 ID。
- `proxy`：代理地址的密钥化摘要，不保存代理凭据明文。
- `snap`：Snap token 摘要。

## 旧协议适配

`LegacyProtocolAdapter` 只按需加载相邻旧项目中的以下底层模块：

- `GojekClient`
- `GoPayPayment`
- `sms_helpers`

适配层不导入 `gopay_protocol_worker.py` 或 `payment_inbox.py`，因此不会走旧版 JSON 任务状态管理。首个业务任务 `account.refresh` 从新数据库解密账号资料，申请账号/代理租约，刷新令牌和余额后在一个事务中更新 `accounts`、`account_secrets` 与 `change_log`。

## REST 与实时更新

任务和账号 API 均要求管理员会话；写接口额外要求 CSRF 校验。任务载荷、检查点、结果和账号密钥不会出现在列表响应中，仅返回 `has_payload`、`has_checkpoint`、`has_result` 标记。

`GET /api/v1/realtime` 使用标准 SSE：

- 事件 ID 等于 `change_log.sequence`。
- 支持 `Last-Event-ID` 和 `after` 断点回放。
- 默认每 15 秒发送中文心跳注释。
- 事件只包含资源 ID、状态、操作和公开摘要，不包含任务密文。
