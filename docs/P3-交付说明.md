# P3 交付说明：GoPay 账号协议状态机

## 阶段结论

P3 已完成。注册、已有账号登录、SMSBower、OTP 和 PIN 流程已接入 SQLite 持久化队列。每个账号流程由固定 Worker 池执行，在等待 OTP 时释放 Worker，收到输入后从加密检查点继续。

## 任务类型与入口

- `account.register`：手动手机号或 SMSBower 自动取号注册。
- `account.login`：已有账号 PIN/OTP 一阶段登录、可选二阶段 OTP 与 PIN 修改。
- `POST /api/v1/account-flows`：根据号码来源创建单任务或 SMSBower 批次。
- Vue“注册与登录”工作台：设置数量、批次并发、代理、PIN 和页面内 OTP。

## 可恢复状态

检查点保存当前阶段、手机号、短信激活 ID、已消费验证码哈希、代理和协议认证状态。检查点使用 AES-GCM 加密，API 仅返回 `has_checkpoint` 标志。

注册主要阶段：

~~~text
prepared → signup_otp_sent → signup_otp_verified → account_created
         → pin_otp_sent → pin_ready → succeeded
~~~

登录主要阶段：

~~~text
prepared → login_1fa_otp_sent/PIN → login_1fa_verified
         → login_2fa_otp_sent → authenticated
         → pin_otp_sent/PIN 修改 → pin_ready → succeeded
~~~

远端只读或可重复步骤的短暂错误进入指数退避；账号创建、PIN 设置和 PIN 修改等副作用请求的结果不确定时进入 `needs_review`。

## SMSBower

- API Key 加密存储，读取接口仅返回脱敏值。
- 兼容 P0 导入的 `legacy.sms.*` 配置键。
- 自动申请号码，持久化激活记录，已消费 OTP 仅保留 SHA-256 哈希。
- 自动取码超时后进入 `waiting_input`，页面提交的 OTP 加密保存并在消费后清空密文。
- 账号创建前的永久错误会尝试释放未使用号码；已产生远端副作用后保留记录供复核。

## 并发与一致性

- 批次和所有子任务在一个 SQLite 事务中创建。
- Worker 领取时校验 `desired_concurrency`，同一批次的运行任务数不超过期望并发。
- 手机号、SMSBower 激活、代理和已有账号使用统一资源租约，避免并发登录或刷新覆盖令牌。
- 账号、密钥、短信激活、号码状态和 `change_log` 在一个事务中落库。

## 验证范围

- 注册两次 OTP 暂停/恢复和账号密钥落库。
- PIN 登录、二阶段 OTP 恢复和 PIN 修改落库。
- SMSBower 配置脱敏、批次创建与 Handler 注册。
- 固定 Worker 池上限和批次期望并发上限。
- SQLite 批量事件自增序号和 Alembic 模型一致性。
